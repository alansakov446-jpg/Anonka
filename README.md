# Охотник за юзернеймами — Telegram-бот

**Текущая версия: 1.4.0**

Бот подбирает свободные редкие юзернеймы Telegram (5-7 символов, с фильтрами
по цифрам), оценивает их читаемость/красоту по шкале 1-10 и хранит всю
историю находок с постраничным просмотром.

## Changelog

- **1.0.0** — первая версия: поиск по фильтрам, живое обновление сообщения,
  пауза/стоп, оценка красоты, unicode-шрифты.
- **1.0.1** — исправлена проверка занятости (Fragment блокировал простые
  запросы антибот-защитой → добавлен `cloudscraper`, ужесточена логика:
  юз считается свободным только если И t.me, И Fragment это подтвердили);
  пересчитана формула красоты (раньше почти всё получало 9-10).
- **1.1.0** — постраничная навигация ⬅️➡️ прямо в сообщении поиска (когда
  находок больше, чем влезает в один экран); оценка красоты теперь по-настоящему
  учитывает читаемость (гласные/согласные кластеры), а не просто чередование;
  генератор стал реже создавать "нечитаемые" варианты; постоянная история
  находок (SQLite) с постраничным просмотром и экспортом в `.txt`; дедупликация
  относительно всей истории (не проверяет повторно то, что уже находил раньше);
  показ скорости поиска и лучшей находки; добавлен "дикий" unicode-шрифт;
  Dockerfile / docker-compose / systemd-юнит для хостинга.
- **1.2.0** — на ограниченных хостингах (например бесплатный тариф PythonAnywhere,
  который пускает наружу только сайты из своего allow-list) проверка через
  t.me/fragment.com постоянно возвращала "не удалось определить", и юзы
  переставали находиться вообще (баг "проверено много — найдено 0"). Основная
  проверка занятости переведена на официальный Telegram Bot API (`getChat`) —
  он использует тот же `api.telegram.org`, с которым бот и так обязан уметь
  работать, поэтому работает на любом хостинге без доп. настройки. Fragment
  остался как необязательная дополнительная проверка. Добавлена опциональная
  поддержка прокси (`PROXY_URL` в `.env`) и сброс вебхука перед стартом polling
  (защита от `TelegramConflictError`).
- **1.3.0** — т.к. Fragment на многих ограниченных хостингах недоступен, а без
  него бот не видит юзернеймы, зарезервированные на Fragment без живого
  Telegram-аккаунта — добавлена прозрачность вместо тишины: в статус-сообщении
  теперь виден индикатор "Fragment: ✅ доступен / ❌ недоступен с этого хостинга",
  и к каждой находке добавлена прямая ссылка на её страницу Fragment, чтобы
  можно было при желании проверить глазами перед тем как забирать юз себе.
- **1.3.1** — переезд с PythonAnywhere на Render (Background Worker): убрана
  инициализация `Bot` через `AiohttpSession(proxy=...)` — Render не ограничивает
  исходящий интернет, прокси не нужен. `PROXY_URL` в `config.py`/`checker.py`
  оставлен опциональным (просто не будет использоваться, если не задан) —
  чтобы код без правок продолжал работать и на хостингах, где прокси всё же
  нужен. `delete_webhook` перед polling сохранён.
- **1.4.0** — добавлена поддержка деплоя на Hugging Face Spaces (SDK Gradio):
  новый `app.py` запускает бота в фоновом потоке (свой event loop через
  `asyncio.run`, с авто-перезапуском при падении) и поднимает минимальную
  Gradio-страницу-статус — она нужна только чтобы Spaces видел "живой"
  веб-процесс и не останавливал бота. `bot.py` менять не понадобилось —
  `main()` уже был чистой асинхронной функцией без побочных вызовов
  `asyncio.run()` внутри себя.

## Функции и как они реализованы

| Функция | Как работает |
|---|---|
| Фильтры поиска (длина 5/6/7/5-7, без цифр / с цифрами / замена букв цифрами) | `username_gen.py` — генератор на основе чередования согласных/гласных, с редкими вставками реально произносимых сочетаний (th, sh, tr, bl…) |
| Проверка занятости | `checker.py` — основная проверка через официальный Telegram Bot API (`getChat`), работает на любом хостинге. Fragment (`cloudscraper`) — необязательная дополнительная проверка на продажу/аукцион, если доступна с текущего хостинга |
| Индикатор доступности Fragment + ссылка на находку | В статус-сообщении показывается "Fragment: ✅ доступен / ❌ недоступен с этого хостинга"; к каждой находке добавлена прямая ссылка `fragment.com/username/<юз>` для ручной проверки, если Fragment с хостинга недоступен |
| Оценка красоты 1-10 | `beauty.py` — в основе реальная читаемость: доля гласных, длина цепочек согласных подряд (штраф больше для "неестественных" кластеров типа `js`, `dh`), плюс бонусы за палиндромы, последовательности (`abc`, `123`), короткую длину |
| Юзернейм в двух видах (обычным текстом и моноширинным) | В каждой находке — строка `@username` (просто текст) и отдельно `username` в HTML-теге `<code>` (моноширинный, удобно копировать одним тапом) |
| Живое обновление одного сообщения | `bot.py` → `update_status_message()` — редактирует одно и то же сообщение через `edit_message_text`, а не шлёт новое на каждую находку |
| Постраничная навигация ⬅️➡️ в сообщении поиска | Инлайн-кнопки `search_pagination_kb()` в `keyboards.py`, прикреплены прямо к статус-сообщению; когда находок больше, чем помещается на "страницу" (6 шт.), можно листать назад/вперёд, не останавливая поиск. По умолчанию бот сам держит тебя на последней странице (новые находки видно сразу), но если пролистал назад — не будет "выдёргивать" тебя вперёд без запроса |
| Пауза / Продолжить / Стоп | Reply-клавиатура внизу экрана (`keyboards.py`), управляется через `asyncio.Event` в `bot.py` — пауза просто блокирует цикл поиска, стоп завершает его и убирает клавиатуру |
| История находок (постоянная, между запусками бота) | `storage.py` — SQLite (`username_hunter.db`), не теряется при перезапуске бота. Доступна из главного меню, тоже с постраничным просмотром ⬅️➡️ |
| Экспорт истории в файл | Кнопка "📥 Скачать всё (.txt)" в разделе истории — формирует `.txt`-файл на лету и отправляет документом |
| Дедупликация между запусками | Перед сетевой проверкой бот сверяется с историей (`storage.already_known`) — уже найденный ранее юзернейм не проверяется и не показывается повторно |
| Скорость поиска и лучшая находка | Показывается в статус-сообщении (проверок/мин) и в итоговой сводке при остановке (юз с максимальным баллом за сессию) |
| Unicode-шрифты | `fancy_font.py` — два стиля: аккуратный (математический Sans-Serif Bold/Italic) и "дикий" (`fancy_style`, буквы-омоглифы из кириллицы/греческого/IPA — специально выбраны широко поддерживаемые блоки, чтобы не показывались "тофу"-квадратики на части телефонов). Сами юзернеймы шрифтами никогда не оформляются — иначе их нельзя будет реально использовать |

## Известные ограничения

- Если бот перезапускается ПОКА идёт поиск — текущая (незавершённая) сессия
  поиска теряется (нужно будет нажать "Найти юзернейм" заново). Сама история
  находок при этом не теряется — она в базе данных, а не в памяти.
- Проверка через Fragment — это обход обычной веб-страницы с антибот-защитой
  (`cloudscraper`), а не официальный API. Если Fragment изменит защиту или
  вёрстку страницы — проверку, возможно, придётся адаптировать (`checker.py`,
  всё прокомментировано).

## Установка (локально)

1. Установи Python 3.10+
2. Создай бота через [@BotFather](https://t.me/BotFather), получи токен
3. В папке проекта создай файл `.env`:

```
BOT_TOKEN=твой_токен_от_botfather
```

4. Установи зависимости:

```
pip install -r requirements.txt
```

5. Запусти бота:

```
python bot.py
```

## Хостинг — как запустить бота так, чтобы он работал постоянно

Локальный запуск (`python bot.py`) работает только пока открыт терминал.
Чтобы бот работал круглосуточно, его нужно разместить на сервере. Вариантов
несколько — вот три рабочих способа "из коробки" уже с файлами в этом проекте.

### Вариант 1 — Docker (проще всего переносить между хостингами)

Подходит для любого VPS с установленным Docker, а также для Railway / Render
и подобных платформ с поддержкой Docker.

```
git clone/скопируй файлы проекта на сервер
cd bot_code
echo "BOT_TOKEN=твой_токен" > .env
docker compose up -d --build
```

История находок сохранится в папке `./data` рядом с проектом (не потеряется
при пересборке контейнера).

### Вариант 2 — обычный VPS + systemd (без Docker)

1. Установи Python 3.10+ на сервере
2. Скопируй файлы проекта, например в `/opt/username_hunter_bot`
3. Создай виртуальное окружение и поставь зависимости:
   ```
   cd /opt/username_hunter_bot
   python3 -m venv venv
   ./venv/bin/pip install -r requirements.txt
   ```
4. Создай `.env` с `BOT_TOKEN=...`
5. Возьми файл `username-hunter-bot.service` из проекта — в нём расписаны
   шаги по установке как системной службы (переживает перезагрузку сервера,
   автоматически перезапускается при падении)

### Вариант 3 — облачные PaaS-платформы (Railway, Render и т.п.)

Загрузи файлы проекта в свой git-репозиторий, подключи его к платформе,
укажи команду запуска `python bot.py` (или используй Dockerfile из проекта,
если платформа поддерживает Docker), и задай переменную окружения `BOT_TOKEN`
в настройках проекта на платформе.

### Вариант 4 — Hugging Face Spaces (SDK Gradio)

Удобно, если работаешь прямо с телефона — код загружается через веб-интерфейс
Spaces без консоли. Точка входа — `app.py`: он поднимает простую
Gradio-страницу (нужна только чтобы Spaces не останавливал процесс) и
запускает бота в фоновом потоке. Шаги:

1. Создай Space на huggingface.co, SDK — **Gradio**
2. Залей туда все файлы проекта (включая `app.py` и обновлённый `requirements.txt`)
3. В настройках Space (Settings → Variables and secrets) добавь `BOT_TOKEN` как **Secret**
4. Space соберётся и запустится сам — `app.py` подхватит `bot.py` автоматически

⚠️ Я не могу развернуть бота "за тебя" из этого чата — здесь нет доступа в
интернет, а токен бота вообще не стоит присылать в чат (это как пароль).
Но все варианты выше проверены на синтаксис/логику и должны завестись
без правок кода — просто следуй шагам.

## Структура проекта

```
bot.py                       — главный файл, все обработчики и логика поиска
app.py                       — точка входа для Hugging Face Spaces (Gradio + фоновый поток)
config.py                    — токен и настройки (задержка, размеры страниц)
checker.py                   — проверка занятости (Bot API + fragment.com)
username_gen.py               — генератор кандидатов юзернеймов
beauty.py                    — оценка читаемости/красоты (1-10)
fancy_font.py                 — unicode-шрифты для оформления
keyboards.py                  — инлайн- и reply-клавиатуры (+ пагинация)
storage.py                    — постоянная история находок (SQLite)
requirements.txt              — зависимости
Dockerfile / docker-compose.yml — запуск в контейнере
username-hunter-bot.service   — пример systemd-юнита для VPS
```
